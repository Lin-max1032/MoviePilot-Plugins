# PT 站点自动打开配置体验设计

## 目标

调整 PTSiteOpener 的配置表单，使其符合 MoviePilot V2 前端组件约定：

- 远程 CDP 地址默认为空，可以先保存配置。
- 计划任务使用宿主内置的 `VCronField`，点击输入框后弹出 Cron 周期计算器。
- 插件作者统一显示为 `Lin-max1032`。
- 保留 1.3.0 中的站点 Cookie 复用、手动 Cookie 回退、通知和立即执行行为。

## 方案

### Cron 表单

使用 MoviePilot-Frontend 已注册的全局 `VCronField` 组件替换当前的 `VTextField`。组件配置继续绑定现有的 `schedule` 模型字段，并传入中文标签和五段 Cron 占位符。

`VCronField` 负责点击输入框和弹出计算器，计算结果仍然是字符串形式的五段 Cron 表达式。后端继续使用 `CronTrigger.from_crontab` 校验并注册计划服务，因此既有配置无需迁移。

### CDP 地址为空

将默认 CDP 地址和表单模型默认值改为空字符串，输入框只显示示例占位符，不再预填具体远程地址。

空地址不是配置解析错误：

1. 插件可以保存配置。
2. Cron 合法时插件状态和计划服务仍按启用状态注册。
3. 计划任务或立即执行尝试连接时，连接层抛出明确的“未配置远程 CDP 地址”错误。
4. 现有执行结果、日志和通知路径负责输出该错误，不发起网络请求。

非空地址继续使用现有 HTTP/HTTPS 校验；非法非空地址仍使配置无效。

### 作者和版本

将 Python 插件元数据作者修改为 `Lin-max1032`，市场元数据保持相同作者。此次用户可见配置行为变化使用补丁版本 `1.3.1`，并在 `package.v2.json` 增加版本历史。

## 测试策略

- 验证默认模型中的 `cdp_url` 为空，非空合法地址仍可启用。
- 验证空 CDP 地址的立即执行记录未配置错误。
- 验证 Cron 表单节点为 `VCronField`，保留 `schedule` 模型、标签和占位符。
- 验证插件作者和市场版本元数据为 `Lin-max1032` / `1.3.1`。
- 运行现有 PTSiteOpener 测试，确保 Cookie 注入、手动 Cookie 回退、通知、立即执行和标签页清理行为不变。

## 非目标

- 不修改 Cron 表达式的存储格式或 APScheduler 调度方式。
- 不实现插件自有的 Cron 计算器。
- 不改变 CDP 地址非空时的连接、WebSocket 解析和错误处理流程。
